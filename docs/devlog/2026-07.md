### 启动主题与 ThemeProvider 异常值一致性（CC-WEBPERF-20260728-004-R1，dry-run 未 commit）

**问题 / 起因**：Codex 审核 004 发现 P2：`index.html` 启动脚本把非法 `theme-mode` 归一为 dark，但 `ThemeProvider` 的 `useState` 直接吞 `localStorage` 原串；`actualTheme = theme === 'auto' ? systemTheme : theme` 在非法值时走浅色分支（`!== 'dark'`）。结果：深色启动底 → React 挂载 → 浅色应用，仍闪变。

**根因**：启动脚本与 ThemeProvider 规则分叉；非法/旧版值未在 React 侧归一。

1. 新建生产纯函数 `web/classic/src/context/Theme/theme-mode.js`：

   - `resolveActualTheme(mode, systemTheme)`：先 normalize；auto → system；否则 dark/light
   - `themeBackground` / `readStoredThemeMode` / `THEME_STORAGE_KEY` / 色常量
2. `ThemeProvider`：
   - 初始 state：`readStoredThemeMode(localStorage)`（不再 `getItem || 'dark'` 原串）
   - `actualTheme = resolveActualTheme(theme, systemTheme)`（禁止裸三元）
   - `setTheme`：字符串走 `normalizeThemeMode`；boolean 仍 true→dark / false→light；其它类型仍默认 `auto`；写入 `THEME_STORAGE_KEY`
3. 测试：
   - `theme-mode.test.js`：直接 import 生产函数；ThemeProvider 源码契约；**用 vm 执行真实 head 内联脚本**，断言非法值 paint dark，并与 helper 全 fixture 对齐

4. **未改** i18n / 路由 / Hero / Logo·spinner（保持 004 纯色启动层）；`index.html` 规则本已与 helper 一致，无需改脚本语义。

**背景**：`Doubao-tts2.0` 调用报 `resource ID is mismatched with speaker related resource`，只有 1.0 能通。用户反馈"2.0 音色应该是参数，不需要单独订阅"，触发深入调查。

- 错误码页（`/docs/6561/2534853`）：`resource ID is mismatched` 的官方排查清单是「服务未开通 / 音色 ID 拼写错 / 复刻过期 / 音色无权限」。

**根因（三层）**：

1. **API 层**：`relay/channel/volcengine/tts.go` 的 `openAIToVolcengineVoiceMap` 把 `alloy` 绑到 1.0 音色 `zh_male_M392_conversation_wvae_bigtts`，其余 5 个别名是 2.0 音色。调 `Doubao-tts2.0` + `voice:"alloy"` → 2.0 resource + 1.0 音色 = mismatch。文档示例全用 `voice:"alloy"`，雪上加霜。
